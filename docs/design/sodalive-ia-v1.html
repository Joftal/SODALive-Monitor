0.2 四条设计原则

后续任何争议回到这四条裁决；优先级：可读性 > 一致性 > 效率 > 美观
1 · 平台色只表身份平台色（Panda 粉 / SOOP 电光黄）只出现在徽标、色点、工作区分段选中态，永不做按钮底色、进度条或正文色。两平台混排时颜色不会被误读成「状态」，SOOP 工作区里也不会每枚主按钮都在替另一个平台说话。
2 · 色彩不做唯一编码任何用色传达的信息（在播 / 离线 / 录制中 / 降级 / 熔断）必须同时有文字或图形。现状顶栏轮询状态只有一枚圆点，色盲用户与深色主题下都读不出含义。
3 · 差异显式声明平台能力不对称处写「不适用」并给一句原因，不隐藏区块。隐藏会让用户以为功能坏了（现状：SOOP 播放页的保活与备用线路整块消失）。
4 · 一屏一个主行动卡片主按钮恒为「进入房间」，录制是次级按钮，关注与取关收进右键菜单和离线行。解决现状卡片上关注 + 录制 + 删除三枚同级按钮互相抢注意力。

L · 工作区怎么摆这三个模块

你指出的问题成立：单页三段滚动会把内容量最大的两个模块互相挤开。关注在播 30 位时，发现段要滚过两屏才露头；发现段自身 240 个房间还要再分页。 两个都需要「整屏 + 各自排序 + 各自分页」的模块被缝在同一条滚动流里，谁都用不痛快。
本质冲突是：关注（管理型，要全量可见、要排序分页）和 发现（浏览型，要沉浸、要分页）是两种阅读模式，不该共享一条滚动轴。 下面三个候选方案，线框 + 代价都摆出来。

L.2 推荐方案 A 的完整规则

「分段切视图」的安全性原来记在一条在播坞上（㉖ 收窄、落地后整体撤掉）；如今「我关注的人有没有开播」由分段第一档的计数 + 顶栏徽标回答
部件规则
视图分段三项：在播关注（计数）· 站内发现（计数）· 离线关注（计数）。每项自己的排序 chips、筛选 chips、分页、滚动位置，全部持久化在 store（沿用现状 exploreFilter 的做法，扩成 per-view）。切换不重新拉数据，只换渲染。落地订正（2026-10-01）：筛选条右端那句常驻说明「排序与页码在本视图内记忆」已撤 —— 记忆是这一屏的默认行为，不是一条需要提醒的规则，天天说反而成了噪音（与 §键盘 那条同源：屏上的说明书只在「用户会撞见却不自知」时才值得占一格）。右端现在只在真有搜索词时出声（「「{kw}」的搜索结果」+「清除搜索」出口），无搜索词时连为顶住那句而摆的 flex-1 一起收起；ws.memoryHint 双语死键一并删，由 D35 锁死。per-view 记忆本体（排序/筛选/页码/滚动位存 store.views）不动。
默认视图进工作区恒为「在播关注」。有关注开播时不自动跳视图（现状 MonitorView 会自动切 tab，会打断正在浏览的用户），改为顶栏平台徽标计数转红——用户回来时看得见，但当前阅读不被劫持。原稿在这里还挂了「在播坞对应头像左侧 2px 品牌色竖条」，坞撤掉后这条信号只剩顶栏一处。
在播坞已整体撤掉（2026-10-01）。原规格留档：sticky 在工作区内容顶部、高 44px，只列「关注且在播」（不含发现段房间），按开播时间新→旧，单项头像 + 昵称（录制中加红点、密码房加锁形），超过 7 个折叠为 +N，右侧「全部在播 N ›」跳「在播关注」视图，0 位时整条收起不占位，「在播关注」视图本身不挂（⑥ 管空态不占位、⑦ 管重复呈现，两条独立判据，见 ㉖）。撤它的理由就是 ⑦ 那条判据推到底：分段第一档已经写着「在播关注 N」并带呼吸点，顶栏徽标在别的页面也报同一个数 —— 一条只读、不承载任何管理动作的头像带，在同一屏上是第二批呈现，而不是补缺。随撤：LiveDock.vue、dock.* 四键（中英各两）、只喂它的 store.liveAnchors getter、原型样式 .livedock / .dchip。由 D38 锁死。
SOOP 的发现项分段仍显示三项（按你确认的 D2 方案 1），但该项右侧带 未开放 灰标；点进去是引导卡而不是空墙。段位置固定，二期接口确认后无缝替换，导航不动。
深链#/:plat/live?view=live|discover|offline，默认 live。旧 #/explore → ?view=discover、#/monitor → ?view=live，语义精确不再靠「滚动到某段」这种不可控行为。
键盘焦点不在输入框时，1 / 2 / 3 切视图；/ 聚焦搜索（现状搜索已在顶栏）。这条让「切去发现逛一圈再切回来」几乎零成本，抵消方案 A 唯一的缺点。落地订正（2026-10-01）：快捷键本体照旧，屏上那条常驻提示（分段行右侧的「按 1 / 2 / 3 切换视图 · / 聚焦搜索」）已撤 —— 它是一排分段右侧的第三条声音（分段本身 + 计数药丸 + 一句说明书），而它讲的动作不需要被看见才会发生：键盘是自己会敲的人用的，撞见一次就记住了。文案与 ws.keyHint 双语键一并删（判据是「无消费方即删」），由 D34 锁死。
每视图的分页底栏常驻，样式与现状大厅一致（共 N · 每页 20 + 页码）。离线关注视图额外给「每页 40/60」选项——它是紧凑行，一屏能放 10 行，20 条太少。
跨视图搜索顶栏搜索词按当前视图过滤；命中数在其他两项上以次级数字显示（分段标签右侧计数在搜索态临时改为该词命中数），所以不会出现「搜 lck 时离线视图显示 6 但其实只有 1 个匹配」。
方案 A 相对你原话「希望平台 tab 独立」的取舍说明：分段切视图会牺牲「一屏看全」，换来的是内容量最大的两个模块各自可用整屏与各自分页。 如果你的真实使用习惯是「大部分时间只看关注，偶尔逛发现」，A 是对的（发现被藏一层无所谓）。 如果是「经常边逛发现边看关注在播」，B 的双栏更贴合，代价是窄窗口要退化。在播坞是 A 用来把 B 的好处补回来的部件，所以我的建议是 A + 坞； 若你更想要 B，我按 B 重画 S1/S2 即可，只是要接受 SOOP 工作区在发现段落地前是「左列表 + 右引导卡」的形态。 〔落地后订正：这条「补回来的部件」最终没留住 —— 分段第一档的计数与顶栏徽标已经回答同一个问题，坞撤掉后 A 由此变成纯粹的「一次一视图」。〕

4.1 录制 / 库为什么不按平台拆成两级页

㉔ 首屏就绪不等官方登录校验（2026-09-30 实机截图审查发现，typecheck / verify / build 全绿而界面是空的）：store.init() 原本把 authState() 放进 await Promise.all，而它是两串官方接口（Panda login_info + SOOP get_private_info，且两平台串行）；网络被黑洞或风控拖住时，ready 不翻转，整个 <main> 只剩一行居中的「加载中…」——实测十几秒，用户读作「软件坏了 / 这一页是空白页」。现首屏门禁只等本地取数（实测就绪 1.0 秒），账号校验照发但不阻塞、结果经 EV.account 回挂，两平台改并行取。态未回填前不能写「未登录」：顶栏胶囊与账号页分段一律落「校验中」一档，账号页大状态卡用独立的 mode: 'checking' 而不是复用 'none' —— 复用会把「立即重新校验」那一行一起藏掉，而「退出登录」在校验中是一枚空承诺，故只在 ok / warn 出现。由 D15a–h 锁死。

㉘ 零数据页的下半屏交给空槽，不交给裸页面底：㉕ 把空态收成有界卡后，实测录制页仍有 380px 的空白落在框外（页面短于视口时，剩余高度什么也不属于）。现录制页正文列 min-h-full flex flex-col，「进行中」空态改成会长高的空槽（flex-1 + min-h-[200px]，实测 1380×860 下 538px、1024×660 下 338px），留白因此被边框收进「这一栏在等任务进来」的语义里；槽内内容贴顶而非居中 —— 居中会让一行小字飘在 538px 框的正中，只是隔了一层边框的「整屏一行小字」，正是 ㉕ 要反对的样子。库为空仍是底部一行提示（页头已有一只大空槽，同一屏摆两只空盒子是自我重复）。账号页实测余量 85px，不动。由 D15o 锁死。
